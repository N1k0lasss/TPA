Arquitectura General del Sistema El proyecto **InvenShop** se estructura como una **aplicación web monolítica basada en el patrón MVT (Modelo-Vista-Plantilla / Model-View-Template)** 1-3. Esta arquitectura desacopla la persistencia de datos, el procesamiento de la lógica de negocio y la presentación visual, garantizando la separación estricta de responsabilidades exigida por la cátedra 1, 4\.  \+-----------------------------------------------------------------------------+ \| CAPA DE PRESENTACIÓN \| \| Plantillas HTML5 \+ Django Template Language (DTL) \+ Bootstrap \| \| Herencia base ({% extends %}, {% block %}) \| \+-----------------------------------------------------------------------------+ ^ \| Peticiones HTTP / Respuestas HTML v \+-----------------------------------------------------------------------------+ \| CAPA DE LÓGICA DE NEGOCIO \| \| Vistas Basadas en Clases (CBVs) & Vistas Basadas en Funciones (FBVs) \| \| Control de Acceso (Mixins/Decoradores) \| Carrito en Sesión \| \+-----------------------------------------------------------------------------+ ^ \| Consultas / Mapeo Objeto-Relacional (ORM) v \+-----------------------------------------------------------------------------+ \| CAPA DE DATOS \| \| Modelos Django (\`models.py\`) con ORM Nactivo \| \| Optimización de Consultas (\`select\_related\`, \`prefetch\_related\`)\| \+-----------------------------------------------------------------------------+ ^ \| Motor SQL (django.db.backends) v \+-----------------------------------------------------------------------------+ \| BASE DE DATOS RELACIONAL \| \| SQLite (Desarrollo) / PostgreSQL (Producción) \| \+-----------------------------------------------------------------------------+  \#\#\# Componentes de la Arquitectura: 1\. **Capa de Datos (Models \- ORM)**: Mapeo de la estructura relacional de la base de datos a objetos en Python mediante el ORM nativo de Django (django.db) 5, 6\. Permite definir tipos de datos, restricciones de integridad relacional (ForeignKey) y validaciones a nivel de modelo 6, 7\. 2\. **Capa de Lógica (Views & Routing)**: \* **Enrutamiento**: Descentralizado mediante un archivo urls.py por cada aplicación delegada con include() 8, 9\. \* **Vistas**: Priorización de **Vistas Basadas en Clases (CBVs)** genéricas (ListView, DetailView, CreateView, UpdateView) para la gestión del catálogo y administración 10-14, combinadas con **Vistas Basadas en Funciones (FBVs)** específicas para la manipulación del carrito en sesión HTTP (django.contrib.sessions) 2, 15, 16\. 3\. **Capa de Presentación (Templates & Forms)**: Interfaz de usuario generada dinámicamente mediante el motor DTL, utilizando herencia de plantillas (base.html), inyección segura de formularios estilizados con Bootstrap 17, 18 y protección nativa contra Cross-Site Scripting (XSS) y Cross-Site Request Forgery (CSRF) mediante {% csrf\_token %} 1, 4, 19\. \* **Requisito TPA que la justifica**: Desarrollo de un sistema monolítico e-commerce e inventario con patrón MVT y separación estricta por responsabilidades 2, 3, 20\. \* **Contenido de Clase que la respalda**: Introducción al patrón MVT y ciclo HTTP en la **Clase 6** 1, 21 y flujo de procesamiento HttpRequest / HttpResponse de la **Clase 7** 15, 22\. \--- \#\# 2\.
